## Method
Skeptical-reviewer mode: for each place a *convincing but false* conclusion could arise I first tried to construct a counterexample (scripts against the real fixtures), only then fixed what I could reproduce. Each fix has a regression test that **fails on the old source (19 of 24 initial regression tests fail pre-fix) and passes now**. I also ran a **mutation check on my own guards** (15 deliberate breakages of safeguards: promotion threshold, holdout hiding, answer-in-question gate, distractor grading, sign-flip p, holdout guard, blindness check, approval enforcement, evidence recomputation, trace-completeness, 404 filtering, spend ceiling, per-trial caps …). It found **one real test gap** (nothing proved live trials reserve against the run-wide ceiling) — now covered; the other early "survivors" were an equivalent mutant and a bad pattern. Final state: every mutant is killed. Plus a seeded fuzz test (600 random patches, ≥ 40 accepted) and a property test over all five zoo sites.

## Checked and found sound (no change needed)
Holdout isolation (tools, verifiers, observations, first prompt) — investigator view contains no holdout task or trial, and mutation of that logic is detected; private criteria are unreachable from tools; fabricated citations are rejected; approval hashes bind to the exact manifest (any option change ⇒ new approval; mutation detected); retries are gated and reserved before sending (odd provider responses — null/list content, fenced JSON, truncation, extra objects — fail cleanly after exactly two reserved-and-settled attempts, no hidden spend); atomic artifact writes; every internal link and asset of every zoo site resolves; real Chromium renders all text the inspector believes is visible on all 5 sites with no failed request (the one apparent mismatch was my test comparing tokens across inline elements); fuzzed patches never produce scripts, handlers, external links or changes to assets, are deterministic and never mutate the original.

## Remaining risks (not fixed; none blocks live testing)
1. **Screenshot-only information**: the agent uses vision, but "evidence-backed" and `tool_interface` look at DOM text. A correct answer read from a screenshot counts as passed-not-evidence-backed, lowering the primary metric in both arms symmetrically. Mitigation: the report keeps `passed` and `evidence_backed` separate; check on L1a whether they diverge.
2. **Association, not cause** (stated in the report): findings rest on a statically verified pattern plus ≥ 2 tasks whose trials were inefficient or ran out of budget. A single trial cannot separate agent inefficiency from site structure; only the retest speaks to cause, and with ~6 pairs it is likely `inconclusive`.
3. **Power**: 6 tasks × 1 repeat ⇒ best-case p ≈ 0.031; modest effects will not be detectable; more repeats cost proportionally more.
4. **Hedge detection** is heuristic (known alternatives + hedge words); an unusual evasive phrasing could still pass or a legitimate sentence containing "or" could fail.
5. **Model-integration unknowns remain** (strict-schema acceptance of nested schemas, protocol following, hypothesis quality, per-turn cost; fenced JSON is deliberately *not* repaired and would make structured calls fail until a prompt change) — exactly what L0 measures.
6. **Real-site fidelity** (CSS-hidden text, JS-rendered content, external assets) is untested beyond the zoo; scripts are stripped by design.
7. **Interrupted trial**: if a process dies mid-trial the spend ledger (correctly) refuses to re-attempt that trial id, so the stage cannot resume; continuing needs a new investigation. Safe for money, inconvenient.
8. Multiple comparisons: testing several fixes on one baseline is not corrected.
