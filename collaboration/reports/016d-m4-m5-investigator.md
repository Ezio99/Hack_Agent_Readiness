## What was built
| module | purpose |
|---|---|
| `trials/attribution.py` | Deterministic per-trial attribution: `success`, `success_unsupported` (right answer, evidence not shown), VOID `provider_or_budget` / `infrastructure`, `task_invalid` (needed navigation does not fit the step limit), `agent` (decisive text was shown yet failed; malformed answer; a path of **named** links existed but was not followed), `tool_interface` (page loaded and contains the decisive text, but the model's observation did not), `website` (the unvisited evidence can only be reached through controls with **no accessible name**), `undetermined` (e.g. budget spent before reaching the evidence). Efficiency signals (extra page views over a lower bound, revisits, repeated identical actions) accompany every class |
| `trials/trace.py` | `trace` stage: attributes all baseline trials (write-once `attribution` artifact) and records neutral Observations from **investigation-partition trials only** (per-trial summaries, an aggregate that excludes void trials, per-kind summaries). Holdout trials are attributed for the final report but never enter the investigator's evidence |
| `investigator/tools.py` | 12 generic read-only tools the *model* chooses between: `list_observations`, `get_observation`, `list_trials`, `trial_summary`, `get_step`, `page_text`, `page_dom` (CSS query with computed accessible names), `links_from`, `search_site`, `compare_observation_to_dom` (what the page offers vs what the model was shown), `check_claim` (free deterministic preview of a claim), `request_extra_trial` (**records a request for the owner; runs and spends nothing**). Every fact-bearing result becomes a citable Observation with an `evidence_id`; page-derived text is returned only inside capped `untrusted_page_text`; holdout trials/tasks and `private/criteria.json` are unreachable; every tool output passes `assert_blind` and the call fails closed |
| `investigator/loop.py` | Model-agnostic autonomous loop: the model picks a tool or `finish` each turn (strict flat schema; an off-menu action is refused, never executed), with a tool budget and a "finish now" reminder. On finish, code validates citations, derives the tier (known claim kind ⇒ verifiable; otherwise a falsifiable `prediction` ⇒ **novel, unverified**; neither ⇒ rejected), stores hypotheses, verifies and promotes. Honest outcomes: unusable output / budget exhausted ⇒ `incomplete`, never a silent success |
| `investigator/verifiers.py` | Deterministic verifiers for the closed grammar: `info_absent_on_template`, `control_unlabeled` (also computes a **structural proof** when named links cannot reach the task's evidence), `info_only_after_k_hops`, `step_overhead_vs_minimum`, `repeated_navigation`, `observation_missing_dom_content`, `error_response_on_path`; `inconsistent_content_across_pages` returns `unverifiable` (not implemented, stated plainly). A parameter must also be stated in the hypothesis text. Promotion needs verifier support + ≥ 2 independent supporting tasks (or the structural proof) + a website-side attribution; agent-side kinds (`repeated_navigation`, `step_overhead…`) can never become website findings. Verified-but-under-supported patterns are reported as **"verified pattern, impact not established — NOT a finding"** |
| `investigator/stage.py`, `report.py` | `investigate` stage (skips with a recorded reason when no investigator model is configured; private transcript; tool log, rejections, pending trial requests in the artifact), live manifest (model, endpoint, caps, call budget, prompt hash, attribution hash, task-manifest hash), `report` stage (outcome, hypotheses by tier, findings, supported-but-unpromoted, attribution counts, void count, partition note) |

## Deliberate decisions (please review)
1. **The investigator's system prompt lists the eight generic pattern types** (not planted diagnoses) so that code can verify a claim at all, with explicit language that most sites show few or none. This is a softer form of "not a menu" than D13 described; the alternative (free-form claims only) would make every hypothesis unverifiable. The sealed diagnoses and category labels never appear (guard-checked).
2. **Evidence page paths are visible to the investigator** (where the answer lives is needed to see whether an agent reached it); expected answer **values** and criteria are not.
3. **Holdout trials run at baseline** (so the final report can compare) but are invisible to the investigator and to its observations.
4. **No recommendations, fixes or post-fix evaluation yet (M6).** Novel hypotheses can carry a `proposed_change` string that is stored for M6; nothing turns it into a proposal tonight. "Complete end-to-end" here means task → trials → attribution → investigation → verified/unverified report.
5. Mock mode runs rules + a scripted agent that always succeeds and **no investigator** (a deterministic investigator would be site-specific logic); the report says "not investigated".

## Remaining integration risks
- **Hosted-model unknowns (to be settled by L0/L1a):** strict-schema acceptance of nested `$defs` (TaskProposals) and of the flat `Step` schema (12 nullable fields), prose-prefix frequency, whether Meta follows the tool protocol, hypothesis quality, and cost per investigation turn (history grows each call).
- **Support thresholds** (≥ 2 supporting tasks among ~5 investigation tasks, K = 1) may leave real friction as "verified pattern, impact not established". That is the honest outcome, but it means a live run may report no finding even when a site has a problem; repeats (K ≥ 2) or the owner-approved `request_extra_trial` path address it at extra cost.
- **Attribution is conservative**: many live failures will be `undetermined` or `agent`; that is by design.
- **CI**: one pre-existing electronics browser test raced under parallel shards (fixed in PR #38; the re-run of #37 passed).
- Gate/ledger ceilings across stages are per-`Ledger` instance over one shared file (conservative, not exact per stage).
