# Report 016l — EXP-B implementation (draft PR; offline; nothing applied or run)

Implements the mechanisms the amended pre-registration (`collaboration/proposals/EXP-B-listing-fee-preregistration.md`, PR #49) needs. No model call, no patch applied to any run, no holdout trace opened, frozen tasks and the programme ledger untouched.

## What was added
1. **Owner-selected exploratory proposal** (`investigate/owner.py`, `readiness investigate propose-owner`). Records an owner-authored NOVEL hypothesis (unverified, with a falsifiable prediction, citing existing observations) and a proposal carrying a validated patch from the existing template set. Label everywhere: `EXPERIMENTAL — OWNER-SELECTED change; not an investigator-verified finding`. Never a finding, never promoted; the investigator's own unverified proposals still cannot be auto-applied. `apply_fix` accepts it only through the same exact-manifest approval; its manifest marks `exploratory_owner_selected: true` and carries the fork provenance.
2. **Post-investigation execution on a fork** (`readiness investigate fork SOURCE --id NEW --carry-investigation`). In addition to the paid evidence and the full spending history, a COMPLETED investigator's result is carried: its evidence store as a hash-verified *prefix* (new observations/proposals may be appended; rewriting the carried history halts), `investigation.json`, `recommendations.json`, the site profile and the snapshot. `investigate` and `recommend` are marked imported-done; the investigator is never re-run; approvals are never inherited. Nothing about the plain fork changes.
3. **Placebo (unmodified repeat) arm and fixed execution order** (`evaluate/exploratory.py`, `post_trials`). The retest runs from an approved plan file (`run … --fix PID --post-plan plan.json`, stored write-once as `artifacts/post-plan`, so a changed plan after approval is refused): placebo trials use the ORIGINAL source snapshot and the ORIGINAL frozen instances and criteria; patched trials use the patched snapshot and the re-derived criteria. The execution order is computed deterministically (placebo tasks in plan order, counterbalanced placebo-first / patched-first, then the remaining patched tasks in task-id order), hashed into the manifest, and the stage refuses to run if its recomputed order differs.
4. **Budget enforcement** (`spend_gate.RequestGate`). A gate can now carry several named caps ("scopes") across many trial gates; each is checked on every reservation against reserved + settled amounts read from the durable ledger, so they hold across restarts: patched arm US$0.80, unmodified arm US$0.55, combined US$1.35, plus the existing per-trial US$0.50, per-request US$0.05 and the US$2.05 ledger ceiling. A refused trial is void and halts the stage (existing rule). `run_arm` is now a thin wrapper over the new `run_plan` and behaves as before (baseline stage cap unchanged).
5. **Control integrity.** After every placebo and patched trial the recorded model, profile, profile hash, schema hashes, mode and limits must equal the baseline trial of that task (placebo: also the source snapshot); a mismatch stops the stage ("never compare against a changed control").
6. **Separate exploratory analysis** (`exploratory-listing-v1`). `evaluate_stage` computes the frozen `paired-signflip-v1` verdict exactly as before and, additionally, the exploratory verdict under rules that are written into the post_trials manifest and hashed. `report-final` carries `exploratory_statement` ("… never its replacement"; "not an investigator-verified finding").

## Exact manifest contents (post_trials, exploratory run)
Everything the retest manifest already listed (arms, patched snapshot hash, valid/excluded tasks, model, endpoint, per-trial and per-request caps, ledger ceiling, retries 0, frozen-rule hash) plus: `forked_from` (source run, imported hashes, imported committed spend, `paid_stages_rerun: false`, carried-investigation summary); `exploratory` (label, proposal id and label, the plan, the full rules, `rules_sha256`); `execution_order` and `execution_order_sha256`; `placebo` (tasks, source snapshot hash, and an `identical_to_baseline` block: snapshot, arm-config hash, profile, model, endpoint, per-task frozen-task hashes, plus the runtime check text); `caps_usd` (patched arm 0.80, placebo arm 0.55, combined 1.35, per-trial, per-request, ledger ceiling, imported committed spend and the headroom left by the combined cap); `cap_enforcement`. The manifest requires exactly one applied proposal and K = 1.

## Pre-registered exploratory rules (summary; full text hashed in the manifest)
Primary comparison: contemporaneous unmodified repeat vs patched, per affected task; secondary: imported historical baseline vs patched. Support needs, for every affected task, patched requests <= 75 % of the placebo's, a reduction strictly larger than the noise estimate (max |placebo − historical| over the placebo tasks), fewer page views than the placebo and no lost evidence-backed pass; same-shape control within 3 requests of its placebo, detail-page controls within 1 request of the baseline. Verdicts: `consistent_with_h1`, `not_supported`, `inconclusive_conflicting_comparisons` (the two comparisons fall on opposite sides of the 25 % floor, or the repeat drifted more than 25 % from the baseline: no support is claimed), `uninterpretable` (control moved, trial missing/void, control not identical).

## Review round 1 (two fixes; design, task set, execution order, budgets and the frozen rule unchanged)
**1. Integrity failures survive a restart.** `trials.run_plan` now verifies a trial BEFORE it can be accepted as evidence. On failure the full record is written to `artifacts/trials-quarantine/<trial>.json` (with `integrity_failure`; the trial-data directory is kept) and the stage halts; nothing is written to `artifacts/trials/`, so the failed trial is never counted by the analysis. On a restart a quarantined trial raises `Halt` ("quarantined ... not accepted and not re-run: review it explicitly") before anything is sent - it is neither silently accepted nor silently re-run (and re-spent). Trials that already exist on disk are re-verified on resume instead of being skipped, so an accepted trial whose baseline later changed or was tampered with also halts the stage. Void trials keep their previous handling (recorded, halt, excluded from comparisons).
**2. The approved manifest is what runs, and it is enforced before any paid trial.** Existing machinery (kept, not duplicated): `Pipeline.run` calls `InvestigationRun.require_approval(stage, stage.manifest(ctx))` before `stage.fn`; the freshly recomputed manifest's exact sha256 must have an approval in `approvals.jsonl`, otherwise the stage stops at `awaiting_approval` and nothing is sent. Because the manifest hash covers `execution_order` / `execution_order_sha256`, `exploratory.rules` / `rules_sha256`, the proposal id and label, the plan, `arms[].patched_snapshot_sha256`, `placebo.snapshot_sha256` and the identity block, `caps_usd` and the run/ledger limits, any change of those is a new, unapproved manifest. New in this round (a direct call of the stage could bypass the pipeline, and a recomputation alone is not the approved artifact): for LIVE runs `post_trials_stage` itself requires an approval for the exact hash of the manifest it would run, loads the approved manifest from its write-once artifact `artifacts/manifests/post_trials-<hash16>.json`, checks that the artifact still hashes to the approved value (missing or altered -> `Halt`), and executes from that approved artifact. Non-live runs spend nothing and need no approval.
**Evidence (offline tests added):** quarantine and restart; re-verification on resume; every approved field changes the hash; the pipeline stops before any trial when no, a different, or a mutated manifest is approved (rules, rules hash, each of the three caps, execution order, proposal identity, ledger ceiling); a direct stage call is refused without the exact approval, with an altered approved artifact, and with a code state that no longer produces the approved manifest; with the exact approval the run executes the approved artifact's order. Test file: 38 tests; full non-browser suite below.

## Risks
- The combined cap is mathematically redundant with the arm caps (by the owner's numbers).
- Placebo and patched trials are sequential, not simultaneous (the counterbalanced order mitigates drift; it cannot remove it).
- n = 1 per task per arm: the exploratory verdict is descriptive. The frozen rule will almost surely report `inconclusive` and is reported unchanged.
- The owner-selected proposal path is a deliberate, labelled exception to "only verified findings are applied"; it exists only for owner-selected, approval-gated, exploratory changes.
