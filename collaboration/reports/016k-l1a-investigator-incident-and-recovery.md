# Report 016k — L1a investigator incident, repair and recovery fork (draft PR; nothing executed)

## 1. Incident (L1a site-5, investigator stage)
The approved investigator ran once. The model answered its first request correctly formatted (one prose line, then the JSON step; finish reason `stop`, 1,278 prompt / 124 completion / 7 reasoning tokens, US$0.002125). `compat.recover` validated the answer and then crashed (`'tuple' object has no attribute 'model_dump'`): it assumed the validated model's `action` is Browser Use's **list**, while the investigator's `Step.action` is a **single** tool-call object (iterating a model yields tuples). The loop reported "aborted after 0 model request(s)", `cost 0.0`, and the final report said `no_supported_issue`. The paid request was in the durable ledger but not in the report, and the outcome read like a negative finding.

## 2. Repairs (this PR)
1. **Recovery crash.** `compat.recover` wraps a single action object in a list before recording its action keys; the Browser Use list path is byte-identical in behaviour (existing parser tests unchanged). Regression tests use the incident's *shape* (one prose line + a `finish` step object) with no private content, plus a check that a model without `action` is still handled.
2. **Request accounting.** The investigator wraps its client in a meter that counts at the moment a response (or a provider error) comes back, before any parsing: `model_requests`, tokens (incl. reasoning), finish reasons, cost, provider errors and gate refusals (a `Halt` is raised before sending and is *not* counted as sent). A request whose parse or recovery later fails stays visible. The stage then reconciles the meter with the durable ledger (`accounting`: reserved vs metered requests, settled vs metered cost, unsettled reservations) and flags any mismatch; nothing is invented (no tool call is fabricated, a failed request is never marked successful). A request that fails with a non-provider exception is counted as sent (conservative: it may have been billed); the one existing test that expected otherwise was updated.
3. **Terminal status.** The investigation artifact and the report carry `status`: `completed`, `incomplete_due_to_infrastructure_error` (provider/gate/parsing crash), `incomplete_unusable_model_output`, `incomplete_no_finish`, or `not_run`. A report whose investigation did not complete and that has no findings now has `outcome` = that status (`not_investigated` for `not_run`) plus an `outcome_note` saying this would have been a false negative; genuine findings or experimental proposals are never overwritten. `readiness investigate run/status` print it, the dashboard export carries `run.investigation_status` and the page shows a red "investigation did not complete" notice. The original L1a run is unchanged on disk; its `report-final` still says `no_supported_issue` — read it together with this report.

## 3. Recovery architecture (`readiness investigate fork`, free and offline)
`fork SOURCE --id NEW` creates a **new run directory** that:
- **imports, byte-for-byte and hashed in `fork.json`:** frozen tasks + private criteria, the paid taskgen batches/transcript, the baseline trials and trial data, the shared arm config, the approved taskgen/baseline manifests (provenance only), and the **entire durable spend ledger** (history preserved; the ceiling counts it);
- **does not import:** approvals, the evidence store, the investigator's artifacts/transcripts/reports, evaluation, recommendations;
- marks `taskgen`, `freeze`, `baseline_trials` done (`imported_from`), leaves `inspect` and `trace` pending: they are free, deterministic and re-derive the same observations from the imported evidence (verified: on the real L1a run, in a scratch copy that was deleted, all 10 observation ids were identical);
- only **reads** the source (verified: source tree hash identical before/after; original failed run and its spending history stay as they are).
Investigate in the fork then needs the normal flow: `run <site> --mode live --id NEW …` stops at the investigate gate; the **investigate manifest now contains `forked_from`** (source run and its `run.json` hash, `imported_files_sha256`, tasks-manifest hash, snapshot hash, imported committed spend, the non-inherited source approvals, the source investigation's status, `paid_stages_rerun: false`) and is verified first: any changed imported file, a rewritten ledger history (the imported ledger must remain an intact prefix) or a different re-derived snapshot raises `Halt` before any request. Because the manifest differs from the original, **neither the source's approval nor any other hash applies**: a fresh exact-manifest approval is required, and nothing is sent without it. The fork's gate uses its own request id prefix, so the original attempt remains visible separately in the same ledger history.

## 4. Holdout / protocol check
The investigator reads only investigation-partition tasks and trials (`Workspace`); the fork does not change that code path. Holdout trial files and criteria are carried along only so the later evaluation stays possible; tests show that in a fork the investigator's task set and trial list exclude holdout, and its first prompt names no holdout task. I did **not** open any holdout content: the only things compared were file hashes and observation ids. Residual risk: an engineer with file access to the fork directory can read holdout files (as in any run); the protocol governs what the *investigator* sees.

## 5. Risks and open points
- Real-run dry run (scratch fork, then deleted) gave an indicative fork investigate manifest hash `d7bb1785cdbea6bc459e5f0af64283e6404e2887ab719c985690cd965c275fc2` (`--total-cap-usd 2.05`, default 12 tool calls); the binding hash is the one printed at the gate after merge, because it depends on the merged code.
- The fork imports whole files; it is only valid for runs whose paid stages completed (`inspect`..`baseline_trials` done) and whose snapshot can be re-derived (zoo sites; a crawled site would need its snapshot imported — not supported yet).
- A recovered response is still model output: the prose prefix is dropped by the existing, validated parser; strictness is not weakened.
- The investigator remains non-resumable mid-conversation; a failed fork run needs another fork.
- The cost of one more investigator attempt is unchanged: stage cap US$0.40, per-request US$0.05, ceiling US$2.05 (US$0.633216 already committed).
