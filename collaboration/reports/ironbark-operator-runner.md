# Ironbark local operator runner

Separate loopback-only operator wraps the existing EXP-C paired driver. It prepares a fresh fork from the local historical Ironbark source, applies the owner-selected patch locally, pins the original and modified snapshot hashes, four-task manifest and grading-rule hash, and validates that the reviewed manifest has exactly four tasks in each of the two arms. Explicit user-entered arm caps and the exact manifest hash are required before the paid worker starts. The existing request gate, ledger, trial runner, grading, frozen and exploratory assessment logic and sanitized exporter remain authoritative. Historical artifacts are read only. The new fork and private metadata are in ignored `scanner-data/ironbark-operator`.

The local UI shows the prepared manifest, frozen questions and task limits, per-arm and task status, graded counts and request counts, and the existing sanitized assessments. It has cancellation, an 1800-second overall timeout and export. Cancellation or timeout does not reverse an in-flight request. The Linux worker has a parent-death guard; interrupted jobs do not resume automatically. The locally held source run is an installation prerequisite. See [operator instructions and proposed but unapproved manifest](../../docs/IRONBARK_OPERATOR.md).

Validation: `tests/test_ironbark_runner.py` exercised gates, partial/void status, cancellation, timeout and export checking, plus all eight paired slots with archived trial records substituted for browser/model calls and the existing assessment/export stages; it did not perform live model inference or independently re-grade those fixture records. `tests/test_ab_experiment.py` and `tests/test_investigate_expb.py` passed with the operator tests (57 total before the additional recorded-fixture test). The critical suite passed 214 tests with 17 deselected outside the sandbox; the sandboxed attempt stalled starting test services and was interrupted. Dashboard `npm run build` passed TypeScript, build and distribution safeguard. The loopback page returned 200 and an unauthenticated API request returned 403. No paid model call, deployment, merge or historical evidence change was made.

The first proposed cap is US$0.80 per arm (US$1.60 combined), requiring separate explicit owner approval; it is not a budget authorization. A paid end-to-end run, provider behavior, real cancellation in flight, and actual model costs remain unverified.
