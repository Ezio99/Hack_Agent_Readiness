# Ironbark evidence provenance fix

Execution mode, evidence origin and measurement are separate in existing compatible fields: `run.mode` is the execution path; `evidence_origin.provider` is `real_model`, `dev_fixture`, `scripted`, or `unknown`; and `evaluation.results[].measured` / `effects[].measured` state whether the result is a supported live measurement. A synthetic run carries a write-once `fixture-evidence` marker; it overrides live-mode metadata. The test worker sets that marker before any fixture execution. Loopback development providers retain their existing `dev-provider` marker and notice.

An unmarked live run is verified only when every stored trial has live-mode metadata, correlated successful HTTPS provider request/response records and a successful mirror GET record. Loopback and non-global IP endpoints are treated as development fixtures. Missing, mixed, incomplete or ambiguous provenance yields `unknown` and is not measured. These are recorded metadata checks, not cryptographic proof of an external provider or an agent's behavior.

New effect provenance is set from this origin; legacy stored effects are gated at report and export time without rewriting historical evidence. Report and export proposal status and measured fields do not present an unverified effect as measured. Existing evidence schema and frozen comparisons are unchanged. `LIVE` notices describe execution mode, not proof of a model call. Sanitized export checking is unchanged.

The no-network fixture preflight freshly graded eight schema-valid answers, produced both unchanged comparisons, and exported a `scripted` origin and unmeasured effects despite live job mode. A grader exception produced a failed job without an evaluation. A read-only historical S1 export still identifies its recorded real-model evidence and retains its frozen `inconclusive` and exploratory `not_supported` verdicts. Fixture tests require the ignored local source run; no paid model was called. Full validation and checks are recorded in STATUS.
