# Ironbark operator fresh-grading preflight

The operator `Manager.start` job-control path was exercised with the approved local Ironbark source, the unchanged two snapshots, four frozen tasks and existing paired driver. A test-only subprocess substitutes a fixture server, model and agent output before the trial runner invokes `suite.core.evaluate`. It rejects non-Unix socket creation and never calls a provider. It returns schema-valid, deliberately incorrect ungraded answers and simulated request counts; these are test data, not live model outcomes. The worker uses the real trial runner, grading, arm orchestration, assessment and sanitized exporter.

All eight fixture trials were independently graded on this path. Each received a strict failure and one simulated request; the operator aggregate reported four requests and zero strict passes per arm. The frozen and exploratory assessments completed, and the sanitized export contained the newly graded rows, eight paired trials and the new run ID; it withheld the fixture answer. Provider origin was conservatively `unknown`, but the effect itself is labelled `live` and `measured` because the test drives the live-mode pipeline. This mismatch means the temporary fixture export must not be used as real evidence; fixture effect provenance is not correctly represented by this test. The original source and historical S1 remain unchanged. The fixture is temporary, local-only and depends on the ignored source run; it is skipped when that source is unavailable. It does not validate real provider, browser or paid execution.

A second job injects a grader exception before the first result; its operator state is failed, no task is completed and no evaluation is published. The no-network guarantee is enforced within the test worker, not a new production execution mode. The preflight does not authorize paid execution.

Focused operator, paired-driver and export suite: 103 passed; after tightening the fixture to require schema-valid answers, both fresh-grading cases passed again. Critical suite: 214 passed, 17 deselected (outside the sandbox for its loopback services). No model call, merge, deployment or frozen rule change.
