## 4. Does Fern reproduce the rank-3 effect despite the larger candidate set? Only partly
- **Not in detail visits.** Required navigation (3 pages in B) was met by both successful B runs (26, 30: filter by brand, Picnic Blanket, Reading Lamp, Trail Daypack, 0 overhead), but arm A **opened the answer page four times** in two runs (28, 29; overhead +3 each), so A's mean visits (3.33) exceeded B's (2.33); run 27 (B) opened only one page. The visit contrast is therefore reversed (−1.0), driven by A's re-verification, not by availability being hidden.
- **Yes in requests and cost, in direction:** +2.67 requests and +US$0.031 (B costlier) but about half the Home/Outdoors size, because A was unusually expensive (US$0.090 vs 0.040–0.048 in Home/Outdoors) and B's failed run is partly a tool loop.
- Whether the larger set (8 products, brand scope spanning four categories) matters is unclear: A's long re-verification sequences cited "exhaustive" checks across "20 products", and B's two clean runs matched the oracle path exactly; with 3 runs per cell we cannot attribute the reversal to set size.

## 5. Verification behaviour, revisits, loops, guesses and errors
- **Run 27 (arm B) is the only failure in 30 runs and the only unverified answer.** After applying the brand filter the agent issued **seven consecutive `find_elements` calls** (steps 3–9) asking for `href` attributes, the same tool-misuse loop seen in Kitchen run 12 and Outdoors run 15. Browser Use's budget warnings (requests 9–11) made it reason "budget critical with 2 steps left"; it then opened Picnic Blanket (out of stock), went back, and at the **final step (12 of 12)** answered with the only page it had seen: Picnic Blanket, AR-7573, $48, `available: false`. Its stated reason: "Most expensive in-stock likely Reading Lamp $45 but ID and availability not verified. Return known data." This is an honest but incorrect answer (the product is out of stock, and Reading Lamp is out of stock too); the evaluator marked it FAIL ("does not match the target; does not satisfy task constraints"). Verification was incomplete (1 of 2 higher-priced candidates checked). The failure is a step-budget exhaustion caused by a tool loop, not evidence that hiding availability misleads the agent, although B's required navigation made it more exposed to that exhaustion.
- **Arm A re-verification was the largest seen:** runs 28 and 29 returned to the listing and reopened Trail Daypack three extra times each, repeatedly reasoning that "history claims a full scan but I must re-verify" (seeking to be "exhaustive" over the 20-product list even though the listing already showed stock). Run 25 reopened it once. All three A answers were correct.
- Arm B runs 26 and 30 followed the minimum path (brand filter; descending checks; no revisit). No guess other than run 27's forced final answer.
