## What was built
| module | purpose |
|---|---|
| `recommend/templates.py` | Patch templates keyed by **verified** claim kind, reading only the site profile: `info_absent_on_template` → copy that labelled field into each listing item; `control_unlabeled` → label unnamed **links** from their destination page's heading (never overriding an existing name); `info_only_after_k_hops` → entry-page links to the deepest pages. Each candidate patch is applied to the mirror and **statically re-checked** (the verified pattern must actually disappear); a patch that the safety rules refuse, that does nothing, or has no template is *not offered* and the reason is recorded. | `recommend/stage.py` | `recommend`: one proposal per verified finding that has a valid patch (`basis=verified_finding`, `unvalidated`, risks and "resolution is not an effect" stated); novel ideas with a proposed change become **manual, EXPERIMENTAL, not auto-applicable** proposals. `apply_fix`: the manifest the owner approves lists each proposal, its patch hash, the parent snapshot hash and the **exact resulting snapshot hash**, and states it applies to the LOCAL MIRROR only; on approval the proposal is approved/applied in the evidence store, the patched snapshot is saved under `patched/<proposal>/` and the baseline is untouched. Unverified/manual proposals cannot be selected |
| `sitemodel/patch.py` | One small general addition: `set_attribute … only_unnamed` (apply only where the element has no accessible name) |
| `evaluate/design.py` | The **pre-registered rule** (frozen into the tasks manifest at freeze time, before any trial): paired by task; evidence-backed pass rate (primary) and model requests (secondary); exact paired sign-flip test (Monte-Carlo above 14 pairs); `improvement` needs mean pass delta ≥ +0.25 with p ≤ 0.10, or equal-or-better pass rate with ≥ 25 % fewer requests and p ≤ 0.10; mirror-image `regression`; otherwise `inconclusive`; fewer than 4 usable pairs ⇒ `inconclusive`; any pair with a void trial in either arm is excluded and listed; investigation and holdout reported separately with a consistency flag |
| `evaluate/stage.py` | `post_trials`: re-runs the **same frozen tasks, profile, model and limits** on the patched mirror (shared arm runner, K repeats), after re-checking every task on the patched snapshot — a task whose expected answer changed, or that now fails the acceptance gate (e.g. the patch put the answer on the start page), is **excluded and reported**, not scored. `evaluate`: builds the paired comparison from stored artifacts, writes the `evaluation` artifact and an `Effect` per proposal (a mock/scripted run is stored as a *pipeline check*, never as a measured effect; only live results count). `final_report`: adds recommendations and the evaluation with its caveat |

## Also from your two M5 points
- **Not an exhaustive menu.** The system prompt now says the pattern list "IS NOT A CHECKLIST AND NOT A LIST OF WHAT TO LOOK FOR", that real causes are often something else, that most sites show none of them, and that open-ended falsifiable hypotheses are "equally welcome, often more informative". Novel hypotheses are stored unverified; a test shows an off-menu idea is heard, kept unverified, and never becomes a finding.
- **Attribution stays conservative — and I tightened two places that could have inflated website findings:** (1) support for a website pattern now counts only trials that are clean successes needing ≥ 2 extra page views or failures attributed to website / tool_interface / undetermined; trials attributed to the **agent**, invalid tasks and right-answer-without-evidence runs never count (a test shows a statically true pattern with no supporting trial is *supported but not promoted*, and the outcome stays `no_supported_issue`); (2) the "agent" verdict now requires that **all** required evidence pages were visited and the text shown (before, item names on a listing could trigger it). The remaining limitation is stated: one trial cannot separate agent inefficiency from site structure when the budget runs out, so such trials are `undetermined`, and the before/after retest — not the attribution — is what tests causation.

## Blockers / risks
- None blocking offline work. **Live unknowns remain** (strict-schema acceptance of nested schemas and the 12-field tool schema, protocol following, hypothesis quality, per-turn cost, whether Meta finishes the tasks).
- **Statistical power:** with 6 tasks and one repeat the best possible paired p is 0.031 (all six improve) — an improvement verdict needs a large, consistent effect; `inconclusive` is the likely honest outcome for modest effects. With 4–5 pairs an "improvement" is nearly unreachable at α = 0.10 (4 pairs ⇒ p ≥ 0.125). More repeats or more tasks cost more.
- `post_trials` shares the run's ledger with the baseline stage; the flow sets the ledger ceiling to `stage_cap_usd + 0.15 + 0.40`, so for one fix pass `--stage-cap-usd` large enough for **two** arms (see below).
- No placebo arm yet (a neutral patch of similar size) and no LLM-written patches: the recommendations are template-based; both are deferred as agreed.
