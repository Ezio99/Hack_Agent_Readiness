# Hosted Ironbark evaluation: work in progress

Branch `hosted-ironbark-evaluation` starts from `ironbark-evaluation-runner` at `108a556`. The hosted product is **not implemented or ready to deploy**. This increment makes the snapshot mirror reject external, scheme-relative and backslash/control-character redirects instead of forwarding them. Existing captured snapshots and grading rules are unchanged. Focused mirror tests passed (10, one browser test deselected); the critical suite passed (214, 17 deselected). The first sandboxed mirror test attempt could not bind loopback; the rerun with loopback access passed. No paid call or deployment occurred.

The existing paired driver forks an ignored local source run and is controlled by a localhost-only operator. The separate existing live API is session-protected, executes a different investigation pipeline, and has an in-process job lock; its budget check occurs before that lock. Neither path is ready to be exposed as a public paired service. The public Replay Studio remains a read-only static interface.

A specific isolation gap needs a tested fix: the pinned browser-use SecurityWatchdog checks redirects after navigation completes, and its exact URL rule uses a string prefix. It is not sufficient by itself to prove pre-request origin and port isolation, nor does the mirror redirect check stop agent-initiated navigation or all subresource requests. Hosting also needs an atomic, durable cross-process global spending reservation and concurrency gate, abuse/rate controls, private persistent storage, sanitized-only public routes, worker isolation and restart recovery, and integration of completed exports into Replay Studio. Those components and their fixture lifecycle tests are not implemented in this increment. Do not deploy or enable paid evaluation.

## Durable admission increment

`agent_readiness.hosted.admission.Admission` provides a SQLite transaction-based, single-active-job reservation with a fixed persisted policy, per-client interval, integer microdollar accounting, and conservative retention of the full reservation after failure or timeout. Concurrent admission and restart tests passed (2); critical tests passed (214, 17 deselected). It is an isolated infrastructure component: **no public API or worker uses it yet**, it does not implement automatic reconciliation, and a production caller must supply a trustworthy keyed client identity and reconcile abandoned jobs only after verifying the worker cannot still spend. It is not a claim of complete hosted budget enforcement.

Local isolation probe: Docker's WSL integration is unavailable; `bwrap` could not bring up loopback inside the sandbox. An elevated `unshare --user --map-root-user --net ip link set lo up` succeeded, but no network-isolated Chromium/CDP/snapshot bridge or egress policy has been built or tested. The existing trial process launches the browser, serves a random-port loopback snapshot, connects to browser debugging and calls the model in the same worker. Isolating that whole process removes both the snapshot and provider connections; isolating only Chromium also removes its debugging connection and snapshot access. A deployable alternative is a browser-specific container/network namespace with default-deny egress and narrowly scoped bridges for the mirror and browser control, with model calls retained in a separate constrained worker or provider proxy. It requires a host/container runtime with enforceable network policy and tests proving that redirects, DNS, local services and subresources cannot escape the mirror boundary. No such deployment is configured here.

## Fixed-target API fixture increment

`agent_readiness.hosted.api.create_app` implements fixed-target start, status and sanitized public export routes backed by SQLite admission. The request model forbids all custom fields; the default has no executor and refuses starts before reserving budget. A test-only executor prepares a fresh paired run and uses the network-disabled fixture worker: all eight outputs are newly graded, compared and passed through `export_run` and `public_demo`. Tests also cover simultaneous admission, persistence across a service instance, a failed worker and refusal to export incomplete results. The fixture API tests passed (6); the critical suite passed (214, 17 deselected). The peer identity is HMACed, but the current implementation does not accept or authenticate forwarded client addresses; reverse-proxy deployment requires an explicit trusted-proxy policy.

This is NOT the requested hosted vertical slice: there is no configured live executor, container network isolation, Docker/Compose configuration, Replay Studio integration, per-task public progress, or verified worker-death/restart reconciliation. The API is not mounted by the production service and must not be exposed publicly. Reservations remain conservative across process loss; the API cannot yet distinguish a dead worker from a surviving one. Fixed caps are enforced by admission only if a future executor is independently bound to those same caps. The fixture test proves the API/paired/export plumbing, not real browser or provider isolation.

## Hosted vertical slice (2026-11-02, second session)

Supersedes the "NOT the requested hosted vertical slice" note above for the items listed here. **No paid call, no deployment, no merge.**

* **Browser network boundary** (`hosted/jail.py`). browser-use launches a wrapper instead of Chromium. The wrapper runs Chromium in new user/net/PID/mount namespaces whose network has loopback only, and bridges exactly the snapshot mirror port and the CDP port over Unix sockets. A fresh `/proc` hides the worker's environment, and configured paths (app, data, secrets) are empty tmpfs. Tested in WSL with Playwright Chromium: the mirror is reachable; another loopback port (direct, via 302 redirect, via `<img>`, via `fetch`), the internet, `169.254.169.254` and hidden files are all unreachable; `/proc` lists only jail processes; there are no leftover processes. The full browser-use agent stack ran a graded trial inside the jail. The service runs `jail.selftest()` at startup and refuses to enable evaluations if it fails (observed: it failed closed on a too-long socket path, now a policy error).
* **Production executor** (`hosted/paired.py`). Each evaluation `eval-<hex>` is 1/3/5 repetitions. Each repetition is a fresh `paired-<hex>` fork run by the unchanged `ironbark_runner.prepare` + `run_worker` (`abtest.drive`). The admission reservation (US$1.60 × repetitions, integer microdollars) must equal the manifest caps for every repetition before any trial. One worker subprocess per evaluation, launched from the job thread with a parent-death signal, its own process group and a hard timeout (1800 s × repetitions + 300 s). The provider key is read from a secret file after exec. The jail is required in the worker.
* **Rehearsal mode.** The same pipeline with jailed Chromium and the real browser-use agent, but the scripted mock model. The worker refuses all non-loopback sockets and name resolution. Each run gets `fixture-evidence`, so the exporter labels it `scripted` and measures no effect. The control-integrity check skips only `model`/`mode`; profile, hashes, schemas, snapshot and limits are still enforced (test-covered). Without that relaxation the existing guard correctly halted the first rehearsal.
* **API** (`hosted/api.py`). The only request field is `repetitions` ∈ {1,3,5}. Endpoints: config (model, tasks, remaining repetitions, active job), recent jobs, per-repetition per-task progress with requests/pages/steps/time, per-arm summary, per-repetition frozen/exploratory verdicts, and the sanitized `public_demo` export per repetition. Client identity is an HMAC of the peer address; `X-Forwarded-For` is honoured only from configured proxies. On start, `recover()` kills any surviving worker and marks unfinished jobs `interrupted`, keeping reservations. Security headers/CSP are set; Replay Studio is served from the same origin.
* **UI** (`dashboard/src/studio/HostedEvaluation.tsx`, `#/run`, `#/run/<id>`). Select → Repetitions → Run → live grid → metrics → "Inspect evidence & replay" (opens the export in the existing stages). Watch another visitor's running job, previous evaluations, and Methodology & provenance in details. The mode badge and a rehearsal banner state that it is not a Muse Spark result.
* **Deployment** (`deploy/`). Dockerfile (studio build + Python + Playwright Chromium, non-root, Chromium file:// blocklist), Compose (app + Caddy TLS, fixed proxy address, Docker secret, read-only source-run mount, `cap_drop: ALL`, seccomp/apparmor/systempaths unconfined for the namespaces), and `DEPLOY.md`. **Not built or run: Docker is unavailable in this WSL.**

Validation: a local rehearsal over HTTP (`serve` → `POST {"repetitions":1}`) completed 8/8 jailed, graded trials in 1:26. The export was complete, `evaluation.state=evaluated`, `evidence_origin=scripted`, `measured=false`, with a storyboard. Screenshots were taken at desktop and 390 px. Tests: see STATUS.

Remaining before judges can run live: (1) owner authorization for `live` mode, the hosted ceiling (US$1.60 per repetition reserved, never released; 5 repetitions reserve US$8) and the public deployment; (2) a Linux host with Docker, where the image build and the jail self-test inside the container must be verified (seccomp/AppArmor/userns host settings in `DEPLOY.md`); (3) the first genuine 1-repetition live run, then 3 and 5; (4) copying the private source run to the host. Known limits: one evaluation at a time (sequential repetitions: a 5-repetition run can take up to 2.5 h at the caps); reservations are never released, even after cheap runs; file:// to non-hidden system paths is still readable inside the jail (no secrets there by construction; Chromium policy also blocks file://).
