## 3. Can the current tasks and metrics support the experiment? Gaps, stated plainly
1. **The frozen rule cannot return `improvement` here.** The pre-registered rule (`paired-signflip-v1`, alpha 0.10, pass-delta floor 0.25, request floor 25 %) pairs *tasks* (6 pairs, K = 1). Best case computed with the real code - both affected tasks pass in 3 requests, everything else identical - gives pass delta +0.167 (< 0.25), request change -42.6 %, p_requests = 0.50: verdict **`inconclusive`**. An exact sign-flip needs at least 5 tasks moving in the same direction (min p 0.0625) and only 2 tasks can be affected. The rule stays in force and will be reported unchanged; it is not a fair test of this hypothesis.
2. **No variance estimate:** baseline K = 1 per task. A 13-request trial may vary between runs without any change; one control task is the only (weak) noise indicator. A comparison against a different day's single trial is also exposed to model/API drift.
3. **Placebo / unmodified repeat was not implemented** in the live flow (plan item M8); PR #50 implements it.
4. **Missing mechanism for an owner-selected change (now implemented in draft PR #50):** `apply_fix` accepts only auto-applicable *verified-finding* proposals, and none exists. Needed offline code: record an owner-authored (novel, unverified) hypothesis plus an owner-selected proposal carrying the patch ops, labelled EXPERIMENTAL, still behind the approval gate; plus a way to run the post-investigation stages for a completed fork (stage statuses currently `done`).
5. **No stage cap existed for `post_trials`**; PR #50 adds durable arm and combined caps and lists them in the manifest.
6. **Holdout is no longer blind for the owner:** the baseline holdout failures were seen before this choice. The patch was derived from the investigator's blind observation, but the holdout result can only be reported as a *non-blind* consistency check.
7. **Metrics measure effort and correctness only;** not answer quality, not navigation (no `reach_page` task), and the `condition` / `copies available` / `next available` fields stay untested.

## 4. Pre-registration (amended; to be fixed by the owner's approval before any trial)
**H1 (exploratory, directional):** showing the daily fee in each `/tools` listing item reduces browsing effort on tasks whose decisive information is the daily fee, without reducing evidence-backed correctness. **The intervention is owner-selected and experimental; it is not an investigator-verified finding.**
**Fixed roles (not changeable after approval):** affected = `gen-e38eac8644`, `gen-c7c642f78c`; same-shape negative control (has an unmodified repeat) = `gen-0384beb35e`; detail-page negative controls (patched only, compared with the historical baseline) = `gen-0ac84d18d3`, `gen-b05c45672f`, `gen-f2731972ed`.
**Design A+ (approved in principle):** six patched trials (all six frozen tasks) and three unmodified-repeat trials (the two affected tasks and the same-shape control), K = 1 per task per arm.
**Comparisons:** **primary = contemporaneous:** unmodified repeat (placebo) versus patched trial, per affected task; **secondary = historical:** the imported baseline trial versus the patched trial. Both are always reported.
**Primary metric:** model requests per trial on the two affected tasks. **Secondary:** page views; evidence-backed pass; calculated cost per trial; void trials; the frozen-rule verdict (computed and reported **unchanged**).
**The frozen rule is not touched:** `paired-signflip-v1` is computed on historical baseline vs patched exactly as frozen at task freeze and its actual verdict is reported even if `inconclusive` (best case computed: `inconclusive`). The exploratory decision rules below are a separate, labelled analysis and are never presented as its replacement.
**Exploratory decision rules (`exploratory-listing-v1`, hashed into the post_trials manifest; sha256 `f8c25e461c64eb87c0bd77c5e0a38dce0a5721ddfd471a2d2eb35efc4aa6ea99`):**
- *Consistent with H1* only if, for **every** affected task: patched requests <= 75 % of the placebo's; the reduction (placebo − patched) strictly exceeds the noise estimate (max |placebo − historical| over the three placebo tasks); patched page views < placebo page views; no evidence-backed pass is lost relative to the placebo; **and** the same-shape control is within 3 requests of its placebo and each detail-page control within 1 request of its historical baseline; **and** the two comparisons do not conflict.
- *Conflict handling (fixed in advance):* if the contemporaneous comparison would support H1 but the historical comparison falls on the other side of the 25 % floor for any affected task, **or** the unmodified repeat differs from the historical baseline by more than 25 % (drift), the verdict is `inconclusive_conflicting_comparisons` and **no support is claimed**. If the contemporaneous comparison does not support H1 the verdict is `not_supported` even when the historical comparison alone looks supportive (the contemporaneous control governs).
- *`uninterpretable`:* a control moves beyond tolerance, a trial is missing or void, or the control is not identical to the baseline.
**Execution order (fixed before either arm runs; `execution_order_sha256` `824dd4f0f53091dec3a2e8446368e281f534a5d9e1a2d2e8e4e1c8f0f0f0c70` is recomputed and printed from the manifest, see 6):** 1 placebo `gen-e38eac8644`; 2 patched `gen-e38eac8644`; 3 patched `gen-c7c642f78c`; 4 placebo `gen-c7c642f78c`; 5 placebo `gen-0384beb35e`; 6 patched `gen-0384beb35e`; 7 patched `gen-0ac84d18d3`; 8 patched `gen-b05c45672f`; 9 patched `gen-f2731972ed` (placebo-first / patched-first alternate to counterbalance time drift; no interim analysis).
**The unmodified repeat is a genuinely unchanged control:** same frozen task (public task entry hash in the manifest), same criteria and private truth, same source snapshot (`1796c2a3…`), same model, endpoint, agent profile (`suite-v2-compat1`), tool interface, limits and arm configuration (hash in the manifest); verified at run time after every trial against the baseline trial of that task (model, profile, profile hash, schema hashes, mode, limits, and for the placebo the snapshot hash): any mismatch stops the stage.
**Validity checks (each recorded):** patched snapshot hash equals the approved one; detail pages byte-identical; only `/tools` changed; `still_valid` lists all six tasks; re-derived evidence requirements used for the patched arm; fidelity guard unchanged; no void trial; same K and configuration as the baseline; spend reconciles with the ledger; the execution order executed equals the manifest's.
**Stopping conditions (fixed):** stop with no automatic retry on any void or infrastructure error, spend-gate refusal, arm / combined / per-trial cap refusal, bound violation, accounting mismatch, ambiguous request, control-integrity mismatch or protocol violation. No interim analysis.
**Allowed claims:** "consistent with / not consistent with a reduction in browsing effort for this exploratory change on this site and these tasks". **Not allowed:** "proved", "verified finding", any general improvement, any claim about other sites, correctness gains, or the causes of the baseline holdout failures.
**Limitations:** n = 1 per task per arm; one site and one model; effort, not correctness; trials sequential, not simultaneous; a listing change alters what the affected tasks measure (the intended effect); **holdout is not blind to the owner (accepted by the owner) and is never exposed to the investigator**; exploratory by design.
